# 02. Requirements

## Functional requirements

- Admin uploads source documents.
- Backend parses documents with LlamaParse.
- Reviewer checks canonical Markdown and metadata.
- Backend chunks approved documents with parent-child strategy.
- Backend embeds child chunks with BGE-M3.
- Backend stores metadata in PostgreSQL and dense vectors in Qdrant.
- RAG answer uses hybrid retrieval: dense + sparse + RRF.
- Student chat calls `POST /api/v1/rag/answer`.
- Answers include citations and related assets when available.

## Hard retrieval filter

```text
review_status = approved
AND rag_status = published
```

`is_latest` is a ranking preference, not a hard filter. Older versions can still be
retrieved when they are approved and published.

## Roles and permissions

MVP roles:

- `student`: ask questions, view citations, open public related assets.
- `admin`: upload documents, edit metadata, approve/reject, publish/unpublish.
- `reviewer`: review canonical Markdown and approve/reject when this role is enabled.

Backend enforces permissions. Frontend role checks are only UI hints.

## Document governance

- Only approved and published document versions are available to student RAG.
- Admin can set `rag_status = deactivated` to remove a version from student RAG.
- Newer document versions use `is_latest = true`; older versions use `is_latest = false`.
- Confidential or internal documents must not be published to student RAG.
- Citations must be generated by backend from retrieved chunks and must be traceable to source documents.

## Security requirements

- Do not commit secrets to git.
- Store local secrets in `.env`; use a secret manager for production.
- Validate user queries, file uploads, metadata fields, dates, and enum values.
- Validate upload file type and size before ingestion.
- Log important admin actions: upload, metadata change, approve/reject, publish/unpublish.
- Back up PostgreSQL, Qdrant snapshots, and document storage before production use.

## Non-functional requirements

- Do not answer procedural claims without source evidence.
- Do not hard-code official content in frontend.
- Keep API paths under `/api/v1`.
- Keep HNSW tuning and advanced reranking post-MVP.
